## Why

跨会话 Agent 需要可靠恢复用户长期偏好、稳定工作背景和需要持续推进的事项。直接保存聊天摘要会引入临时信息、重复内容、过时判断、跨用户串用和缺乏来源等问题，因此需要建立一套与 Agent 框架和具体业务场景解耦的主动记忆核心。

本变更按绿地系统设计目标方案，不以原有验证性代码的入口、模块、存储或兼容性为约束，为后续投资假设跟踪和调研问题跟踪提供共同基础。变更通过 OpenSpec 分阶段实施；阶段一的通用契约、可信记忆卡片、用户隔离和 SQLite 持久化已经完成，后续阶段继续按任务清单推进。

## What Changes

- 增加候选记忆发现和准入能力，将会话内容区分为自动保存、待确认、丢弃和敏感拦截。
- 增加长期记忆生命周期能力，管理来源、时间、有效性、重复、补充、冲突、替代和历史版本。
- 增加主动召回与使用能力，在新任务中按用户、对象、场景和意图选择少量当前有效记忆，并记录实际使用情况。
- 增加记忆治理能力，强制执行多用户隔离、敏感内容持久化边界、人工确认、修正、撤销、删除和审计要求。
- 明确通用核心与场景规则的边界，使新场景能够定义自己的记忆类型、关系和召回偏好，而不改变核心生命周期。
- 提供与任意 Agent Runtime 对接的写入、查询和管理契约，使记忆引擎可以先作为模块化单体运行，并在需要时独立部署。
- 为后续实现准备可分阶段执行的任务清单和验证场景。

## Capabilities

### New Capabilities

- `memory-capture`: 从已完成的会话或阶段性任务中发现原子候选记忆，判断长期价值、内容性质、所属用户、场景、对象和处理决策。
- `memory-lifecycle`: 管理活动与历史记忆的来源、时间、有效性、业务进展、重复、补充、冲突、替代、版本和场景关系。
- `memory-recall`: 在新任务中检索、筛选和使用相关的当前有效记忆，并向用户说明本轮使用内容及来源。
- `memory-governance`: 管理用户隔离、敏感持久化拦截、待确认内容、人工修正、撤销、删除和审计可见性。

### Modified Capabilities

无。当前 OpenSpec 主规范中尚无已部署能力，本变更仅新增通用记忆能力。

## Impact

- 项目将以独立 Memory Engine 和新的 Conversation Runtime 契约为目标组织，不承诺兼容当前原型入口或内部模块。
- Memory Engine 对外提供摄取、查询和用户管理能力，Agent Runtime 只消费经过治理的记忆上下文。
- 项目需要统一持久保存结构化记忆、向量、来源、版本、关系、使用记录和审计事件，并在数据库与应用边界双重执行用户隔离。
- 自动化测试、合成评测数据和演示交互需要围绕目标架构重建，以覆盖跨会话恢复、冲突替代、跨用户负向案例和用户管理。
- 本变更不接入真实投研数据，不负责验证外部事实，不提供生产级身份认证、合规审计或交易能力。
