## Why

当前质量评估只有少量通用/投研混合案例，离线候选/关系 1.0 来自把金标当作预测的测试基线，容易被误读为模型质量；首轮真实运行还暴露了关系否定/方向误判和语义召回排序问题。现在需要一套以论点、证据、风险、催化剂、研究问题和长期事项为核心的可复现基准，并用真实结果驱动通用能力优化。

## What Changes

- 将评估数据升级为以中文投研任务为主的版本化案例集，覆盖全部投研记忆类型、六种合法关系、语义召回干扰项和金融敏感负例。
- 为案例增加稳定分类，并在报告中输出分类计数/通过率、运行模式、安全模型标识、数据集摘要和耗时，不输出案例正文、身份或 Secret。
- 为 runner 增加显式 JSON 结果输出能力；离线模式只评估召回与安全等确定性任务，候选/关系明确标记为未评测，`--live-model` 才读取 `MEMORY_MCP_MODEL_*`。
- 使用当前 `server/.env` 执行一次真实模型评测，把命令、环境边界、模型标识、聚合指标、失败案例和解释记录到独立评测文档。
- 根据失败案例增强关系抽取的否定/方向约束，并通过 Profile 声明式召回提示改善不同业务场景的排序，不在 Core 中硬编码投研类型。
- 删除评测金标 baseline、测试专用 live predictor 注入和低价值的“测试测试”用例；合并重复结果说明，保持生产核心测试、MCP 工具、Agent 配置、PostgreSQL schema 和发行包边界不变。

## Capabilities

### New Capabilities

- `investment-memory-benchmark`: 投研跨会话记忆的版本化案例、分类指标、真实模型运行与结果记录合同。

### Modified Capabilities

无。

## Impact

- `evals/`：严格数据 schema、投研案例集、指标和 runner 输出。
- `server/src/memory_mcp/`：关系准入保护与 Profile 驱动的召回提示。
- `tests/evaluation/`：保留数据合同、离线隔离、输出安全和显式真实模型开关等高价值测试。
- `docs/`：以评测报告作为结果唯一来源，测试/使用文档只保留入口。
- 外部系统：一次显式真实模型 API 调用批次；不连接 PostgreSQL、不修改运行数据、不增加依赖。
